Mesa 26.2.5 Release Notes / 2026-10-14
======================================

Mesa 26.2.5 is a bug fix release which fixes bugs found since the 26.2.4 release.

Mesa 26.2.5 implements the OpenGL 4.6 API, but the version reported by
glGetString(GL_VERSION) or glGetIntegerv(GL_MAJOR_VERSION) /
glGetIntegerv(GL_MINOR_VERSION) depends on the particular driver being used.
Some drivers don't support all the features required in OpenGL 4.6. OpenGL
4.6 is **only** available if requested at context creation.
Compatibility contexts may report a lower version depending on each driver.

Mesa 26.2.5 implements the OpenCL 3.1 API, but the version reported by
the CL_DEVICE_VERSION, CL_DEVICE_NUMERIC_VERSION and CL_DEVICE_OPENCL_C_ALL_VERSIONS
clGetDeviceInfo queries depends on the particular driver being used.

Mesa 26.2.5 implements the Vulkan 1.4 API, but the version reported by
the apiVersion property of the VkPhysicalDeviceProperties struct
depends on the particular driver being used.

Bug fixes
---------

- Mesa 26.2.1 Ground Truth Ambient Occlusion Broken on No Man's Sky
- Mesh shader uniform/constant rendering issue
- RADV regression in Mesa 26.2.x – No Man's Sky has broken/dark sunlight on RX 7900 XT
- Regression: D3D12 driver and DRI broken under WSL in 25.0.4
- SIGILL with llvmpipe on ARMv9(?) without SVE
- X-Plane 12 encountering a GPU crash on load after recent update.
- [Forts RTS] Corrupt rendering of compressed textures
- aco: illegal VOP3 v_cndmask_b32 with two SGPR operands on GFX6-9 in emit_scaled_op (fp32 denorm preserve) → wrong results
- radeonsi: incorrect rendering in Doom 3: BFG
- radv/amdgpu: padding VM page (RADEON_FLAG_VM_PAD_1PAGE) is never unmapped on BO destroy; VA reuse then fails with "va ... conflict" on GFX9
- rusticl: could not initialize SVM support with radeonsi,zink
- zink: wrong pipeline after a vertex-layout-only change without VK_EXT_vertex_input_dynamic_state
